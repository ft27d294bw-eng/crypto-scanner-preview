# Crypto Scanner v0.6 — запуск публічної тестової версії

**Це публічний preview для тестування, не готовий фінансовий продукт.** За замовчуванням реєстрація email **вимкнена**. Профіль, фото і портфель зберігаються лише у браузері користувача. Live-котирування залежать від доступності публічних API; демоцінники позначені як приклади. Не збирайте паролі, гроші або особисті фінансові дані.

## Шлях без термінала — GitHub + Render

1. На Mac розпакуйте `CryptoScanner_PUBLIC_PREVIEW_READY.zip`. Відкрийте **папку** `CryptoScanner_PUBLIC_PREVIEW`.
2. Створіть GitHub-акаунт (якщо немає): https://github.com. Натисніть **New repository**, ім'я `crypto-scanner-preview`, оберіть **Private**, **не** додавайте шаблон README/.gitignore.
3. На сторінці порожнього репозиторію оберіть **uploading an existing file** (або `Add file` → `Upload files`). Перетягніть **весь вміст** папки `CryptoScanner_PUBLIC_PREVIEW` (файл `render.yaml`, `server.js`, `package.json`, усю папку `public/`, `lib/`, `tests/` тощо) — так, щоб `render.yaml` був на верхньому рівні репозиторію, а не всередині додаткової папки. Збережіть через `Commit changes`. **Ніколи не завантажуйте `.env`, `data/`, `users.sqlite`, приватні ключі чи паролі**.
4. Увійдіть на https://dashboard.render.com та під'єднайте GitHub у процесі створення сервісу. Створіть **New → Blueprint**, виберіть репозиторій `crypto-scanner-preview` та підтвердіть конфігурацію з `render.yaml` (план **Free**). Якщо інтерфейс Render пропонує лише **New → Web Service**, виберіть repo, Runtime = Node, Build Command = `npm test`, Start Command = `npm start`, Plan = Free, Health Check = `/healthz`, додайте `NODE_ENV=production`, `PUBLIC_PREVIEW=1`.
5. Після `Deploy live` Render покаже **вашу унікальну адресу** `https://...onrender.com` з HTTPS. Її не можна вгадати до створення сервісу.
6. Перевірте `https://...onrender.com/healthz` (має бути `{ "ok": true, ... }`), головну, Валюти → USD/CNY, Інвестиції, Портфель, Профіль, Settings → RU/EN, Exchange Lab на головній. Заходьте без `?demo=1`, щоби запросити живі публічні ціни (вони можуть бути недоступні через мережу чи обмеження API). `?demo=1` — лише приклад із вигаданими курсами.
7. Не вводьте особисті паролі й не просіть тестувальників реєструватися: серверні акаунти тут вимкнено навмисно.

## Чому реєстрація вимкнена?

Безкоштовний Render має тимчасову файлову систему: зміни в SQLite можуть зникати під час перезапусків і деплоїв. Для повноцінної реєстрації потрібні постійна база даних / платний диск, резервні копії, підтверджений домен для email, зовнішній аудит безпеки, політика приватності, видалення акаунта й процедури відновлення пароля. Не активуйте `ACCOUNTS_ENABLED=1` для публічного запуску без цих кроків.

## Якщо щось не працює

- Помилка збірки: перевірте, чи `package.json`, `server.js`, `render.yaml`, `tests/` — **в корені репозиторію**. Подивіться `Render → Logs`.
- Помилка Node: `.node-version` у корені має значення `24`; тестуйте `node -v` локально (потрібен Node >=22).
- `503` для бірж або валют: це upstream API, перевіряйте мережевий доступ та статус постачальника. Не підміняйте реальні ціни демоцінниками.
- `503` для `/api/auth/*`: очікувано на public-preview.
- Сайт повільно відкривається вперше: безкоштовний Render може засинати після 15 хвилин неактивності.
- Старий дизайн: зробіть hard refresh / оновіть кеш PWA, service worker v6-public-preview.

## Після першої публікації

Поділіться тестовим URL із 5–10 знайомими, зберіть баги та відгуки. Далі зробимо release з постійною БД, ресетом пароля та реальними поштовими листами, і лише тоді відкриємо реєстрацію.
